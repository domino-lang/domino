# Story 32 — The export tree is never overwritten without `--force`

**Epic:** EasyCrypt Export — read `docs/stories/easycrypt/00-overview.md` first.
**Records:** `docs/adr/0004-the-export-tree-is-never-overwritten-without-force.md`.
**Branch:** `amir/easycrypt-export`
**Depends on:** 05 (the `easycrypt` command and its output layout), 10 (flat layout).
**Blocks:** nothing, but should land **before** 33, which starts producing files worth protecting.

---

## 1. Why this story exists

The owner: *"I don't want the translation to rewrite proofs or any other file but rather give a
warning that is already exists. I want it to give warning as soon as possible. Let it rewrite with
`--force` option."* And on what the warning does: *"give warning and list the files and then
stop!"*

`domino easycrypt` writes its tree with a bare `std::fs::write` per file (`write_files` and
`write_all_observed` in `src/writers/easycrypt/export.rs`) and no existence check anywhere. Two
things in that tree are worth more than the run that would replace them:

- a `Eq_*.ec` whose bullets a **tactics run** proved, possibly over many minutes — story 27 measured
  691 s for kem-dem `PKENC` alone;
- hand-written EasyCrypt someone put there. `example-projects/4WHS/ec4whs/` is exactly that: a
  hand-written development (`full/`, `simple/`, no `(* generated by domino … *)` banner) sitting
  beside a Domino project, untracked.

Both are destroyed today by a re-run, silently, with nothing to recover from.

## 2. Inherited from earlier stories

- **Story 05 / 10:** the output layout. `<out>/<theorem>/` per theorem, flat, default
  `<project>/_build/easycrypt`.
- **Story 21:** the `write` phase. Every theorem is built fully in memory and nothing is written
  until *every* requested theorem has exported successfully — see the comment in
  `crates/domino/src/main.rs`: *"a failed export must not leave a half-written tree"*, extended
  deliberately across the whole invocation.
- Every generated file carries a `(* … generated by `domino easycrypt`. *)` banner (`EcFile::header`,
  7 sites). **This is not sufficient to decide the question** — see ADR 0004: a tactics run's output
  carries the banner too, and is the thing most worth protecting.

## 3. Work to do

### 3.1 The check

Before writing, `<out>/<theorem>/` must contain no file other than a **run artifact** (§3.2). Any
other pre-existing file — `.ec`, `.smt2`, a stray note, anything — stops the run.

- **Scope:** every mode, not just `--tactics`. Plain `domino easycrypt` is the one that clobbers
  today; the hazard belongs to writing, not to tactic generation.
- **Granularity:** only the directories this invocation will write. A run on theorem `A` says
  nothing about `B`'s directory, or the default `_build/easycrypt` becomes unusable for a project
  whose theorems are exported one at a time.
- **All or nothing:** one offending file anywhere stops the whole invocation, consistent with
  story 21's existing rule. The message lists every offending file across every theorem, so one
  run tells you everything you have to move.
- **Failure shape:** a non-zero `miette` diagnostic like the command's other errors. A warning that
  stops the run is an error.

### 3.2 Run artifacts, stated as patterns

A **run artifact** is a file a tactics run writes *about itself* rather than as translation output.
Exempt, because they are regenerated every run and never hand-edited:

- the `progress/` subtree (`index.html`, `ec-transcript.jsonl`);
- the `!debug!/` subtree (lockstep output — see §6);
- `*.report.txt`;
- `alignment.txt`.

**State this as directories and patterns, not as a list of four paths.** A fixed list is complete
today and wrong the moment `docs/stories/symbolic-execution/19-…` moves lockstep output inside the
export tree, at which point every second run would start demanding `--force`.

### 3.3 As early as possible

The check needs only `out_base` and the theorem names, both cheap. Run it **first** in
`easycrypt()` — before the `Session::start` capability probe, before any export work. It is the
failure most likely to fire, and "as soon as possible" is what the owner asked for.

### 3.4 `--force`

Overwrites, restoring today's behaviour. The refusal message names it, and names what it would
cost: `N of M oracles already proved; --force discards them`.

## 4. Acceptance criteria

- [ ] A second `domino easycrypt` into the same directory fails, non-zero, listing the files.
- [ ] `--force` makes it succeed and the output is byte-identical to a first run into an empty
      directory.
- [ ] A directory holding *only* run artifacts (`progress/`, `*.report.txt`, `alignment.txt`,
      `!debug!/`) does **not** block: two consecutive `--tactics` runs need no `--force`.
- [ ] Pointed at `example-projects/4WHS/ec4whs/full` via `--out`, the run refuses and names the
      hand-written files. Nothing in that directory is modified.
- [ ] Multi-theorem: with one theorem's directory dirty and another clean, nothing at all is
      written and both are reported.
- [ ] The check fires before the EasyCrypt probe: with `--tactics`, no `DOMINO_EASYCRYPT` set and a
      dirty directory, the error is the overwrite error, not the missing-EasyCrypt error.
- [ ] A missing output directory, and an empty one, both pass.
- [ ] `cargo build/test/clippy --workspace` clean.

## 5. How to verify

```bash
cargo build --workspace && D=$PWD/target/debug/domino
cd example-projects/kem-dem/kem-dem-cca-ssp
rm -rf _build/easycrypt && $D easycrypt          # writes
$D easycrypt                                      # refuses, lists files, non-zero
$D easycrypt --force                              # writes again
$D easycrypt --out $PWD/../../4WHS/ec4whs/full    # refuses, touches nothing
```

## 6. Notes / risks

- `_build/easycrypt` becomes a build directory that refuses to be rebuilt in place. That is
  deliberate and it is the surprising part; ADR 0004 exists so nobody "fixes" it.
- **Resuming is out of scope** (*"Let's put resuming for future"*). After a stopped tactics run the
  natural next command is blocked and `--force` discards the **partial proof**. The message says so,
  and `--oracle` is the manual workaround. A real `--resume` means parsing tactic scripts back out
  of a `.ec` and trusting them, which is its own story.
- The `!debug!/` exemption is written now against a path that does not exist yet
  (symbolic-execution story 19). That is intentional and costs nothing.
