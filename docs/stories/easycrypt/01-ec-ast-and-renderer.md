# Story 01 — EasyCrypt AST, renderer and identifier mangling

**Epic:** EasyCrypt Export (`domino easycrypt`) — see `docs/stories/easycrypt/00-overview.md`.
**Branch:** `amir/easycrypt-export`
**Depends on:** nothing.
**Blocks:** every other story in this epic.

---

## 1. Why this story exists

The owner's requirement is explicit:

> So a key step is that you create proper data structures for the easycrypt and do not quickly
> generate EasyCrypt as text so the symbolic debugger can be extended to run on this ast.

Story 08 lowers generated EasyCrypt code into the debugger's IR and walks it symbolically. That is
only possible if the exporter's output is a **tree**, with text as its rendering. So this story
builds the AST and its renderer *before* anything translates Domino into it, and nothing later in
the epic is allowed to `format!` EasyCrypt syntax by hand.

This story has **no Domino input at all**. Its tests construct ASTs by hand.

## 2. Inherited from earlier stories

Nothing. But read §8.1 of the overview — the EasyCrypt syntax facts there were verified by
compiling test files and they constrain this AST. The load-bearing ones here:

- Procedure names, program variables, operators, record fields and types must start **lowercase**.
  `proc NewKey` and `var LTK` are parse errors. Modules and module types must start **uppercase**.
- `res` is a keyword, and so are ~150 other words (full list in overview §8.1).
- Record field names are globally unique within a namespace.
- Verified-compiling syntax you will render: `` s.`1 ``, `None<:bits_n>`, `oget e`, `m.[k]`,
  `m.[k <- v]`, `rem m k`, `empty`, `x <$ d`, `r <@ M.p(a, b)`, `{| f = e; g = e' |}`,
  `clone T as N with op o <- p`, `module M = F(A, B)`, `declare module A <: Adv { -M.N }`.

## 3. Work to do

Create `src/writers/easycrypt/` with `mod.rs`, `ast.rs`, `render.rs`, `names.rs`, and register
`pub mod easycrypt;` in `src/writers/mod.rs`.

### 3.1 `ast.rs` — the tree

This is the contract for the whole epic; later stories add variants only when they must. Keep it
free of Domino types — it models EasyCrypt, not Domino.

```rust
pub struct EcFile {
    /// `(* generated by domino … *)` banner, rendered first.
    pub header: Vec<String>,
    pub requires: Vec<Require>,
    pub items: Vec<EcItem>,
}

pub struct Require { pub import: bool, pub names: Vec<String> }  // `require [import] A B.`

pub enum EcItem {
    Comment(String),
    TypeAbstract { name: String },                                   // `type bits_n.`
    TypeAlias { name: String, ty: EcType },
    Record { name: String, fields: Vec<(String, EcType)> },
    OpDecl { name: String, ty: EcType },                             // `op zero_n : bits_n.`
    OpDef { name: String, args: Vec<(String, EcType)>, ret: Option<EcType>, body: EcExpr },
    Axiom { name: String, formula: EcExpr },
    ModuleType { name: String, params: Vec<(String, String)>, procs: Vec<ProcSig> },
    Clone { base: String, as_name: String, overrides: Vec<CloneOverride> },
    ModuleAlias { name: String, functor: String, args: Vec<String> }, // `module M = F(A, B).`
    Module(EcModule),
    Section(EcSection),
}

pub enum CloneOverride {
    Type { lhs: String, rhs: EcType },
    Op   { lhs: String, rhs: EcExpr },
}

pub struct ProcSig { pub name: String, pub args: Vec<(String, EcType)>, pub ret: EcType }

pub struct EcModule {
    pub name: String,
    /// Functor parameters: `(P : Prot_i)`.
    pub params: Vec<(String, String)>,
    /// `: KX_i` — checked structurally by EasyCrypt.
    pub implements: Option<String>,
    pub vars: Vec<(String, EcType)>,
    pub procs: Vec<EcProc>,
}

pub struct EcProc {
    pub name: String,
    pub args: Vec<(String, EcType)>,
    pub ret: EcType,
    /// `var x : t;` or `var x <- e;` (EasyCrypt infers the type in the second form —
    /// always render the type as well, it costs nothing and reads better).
    pub locals: Vec<(String, EcType, Option<EcExpr>)>,
    pub body: EcBlock,
    /// The single trailing `return e;`.
    pub ret_expr: Option<EcExpr>,
}

pub struct EcBlock(pub Vec<EcStmt>);

pub enum EcStmt {
    Comment(String),
    Assign { lhs: EcLvalue, rhs: EcExpr },                  // `x <- e;`
    Sample { lhs: EcLvalue, distr: EcExpr },                // `x <$ d;`
    Call { lhs: Option<EcLvalue>, module: String, proc: String, args: Vec<EcExpr> }, // `r <@ M.p(a);`
    If { cond: EcExpr, then_block: EcBlock, else_block: Option<EcBlock> },
}

pub enum EcLvalue {
    Var(String),
    /// `(a, b) <- e;`
    Tuple(Vec<String>),
    /// `m.[k] <- v;` — only legal when `m` is a program variable of `fmap` type.
    MapSet { map: String, key: EcExpr },
}

pub enum EcExpr {
    Var(String),
    /// Qualified: `Pkg_KX.KX.ltk_map`, or a memory-tagged one in a formula, `M.x{1}`.
    Qualified { path: Vec<String>, mem: Option<u8> },
    Int(i64), Bool(bool), Unit,
    Tuple(Vec<EcExpr>),
    /// `` e.`1 `` — 1-based, as EasyCrypt counts.
    Proj { expr: Box<EcExpr>, index: usize },
    /// `` e.`field `` for records.
    Field { expr: Box<EcExpr>, field: String },
    RecordLit { fields: Vec<(String, EcExpr)> },
    Some_(Box<EcExpr>),
    /// `None<:t>` — always annotated; bare `None` is ambiguous in most positions.
    None_(EcType),
    Oget(Box<EcExpr>),
    MapGet { map: Box<EcExpr>, key: Box<EcExpr> },          // `m.[k]`
    MapSet { map: Box<EcExpr>, key: Box<EcExpr>, value: Box<EcExpr> }, // `m.[k <- v]`
    MapRem { map: Box<EcExpr>, key: Box<EcExpr> },          // `rem m k`
    MapEmpty,
    App { head: String, args: Vec<EcExpr> },                // `func_prf a b`
    Unop { op: EcUnop, arg: Box<EcExpr> },
    Binop { op: EcBinop, lhs: Box<EcExpr>, rhs: Box<EcExpr> },
    If { cond: Box<EcExpr>, then_expr: Box<EcExpr>, else_expr: Box<EcExpr> },
    Let { name: String, value: Box<EcExpr>, body: Box<EcExpr> },
    Quant { kind: Quantifier, binders: Vec<(String, EcType)>, body: Box<EcExpr> },
}

pub enum EcUnop { Not, Neg }
pub enum EcBinop {
    Eq, Ne, And, Or, Xor, Implies,
    Lt, Le, Gt, Ge,
    Add, Sub, Mul, Div, Mod,   // Div/Mod render as `%/` / `%%` (IntDiv)
}
pub enum Quantifier { Forall, Exists }

pub enum EcType {
    Int, Bool, Unit,
    Named(String),
    Tuple(Vec<EcType>),
    Option(Box<EcType>),
    Fmap(Box<EcType>, Box<EcType>),
    Distr(Box<EcType>),
    Fun(Box<EcType>, Box<EcType>),
}

pub struct EcSection {
    pub declares: Vec<DeclareModule>,
    pub items: Vec<EcItem>,
    pub lemmas: Vec<EcLemma>,
}

/// `declare module A <: Adv { -Game_H.G, -Game_H.Pkg_KX.KX }.`
pub struct DeclareModule { pub name: String, pub module_type: String, pub restrictions: Vec<String> }

pub struct EcLemma {
    pub name: String,
    /// `&m (b : bool)` — memory binders first, rendered verbatim in order.
    pub binders: Vec<LemmaBinder>,
    pub statement: EcExpr,
    /// Proof script. **The one place raw text is allowed** — tactics are not modelled.
    pub proof: Vec<ProofLine>,
}

pub enum LemmaBinder { Memory(String), Typed { name: String, ty: EcType } }

/// `bullet` is `+`/`-`/`*` nesting depth handling; `text` is one tactic line.
pub struct ProofLine { pub indent: usize, pub bullet: Option<char>, pub text: String }
```

Rules:

- **No `Raw` variant in `EcExpr`, `EcStmt` or `EcType`.** Proof scripts are the single escape
  hatch. If a later story needs a construct, it adds a variant.
- `Pr[...]` statements in lemmas are expressed with a dedicated `EcExpr::App`-free form? No — add
  one variant when story 07 needs it, and not before. Story 07 is allowed to extend `EcExpr` with
  `Pr { module: String, proc: String, args: Vec<EcExpr>, memory: String, event: Box<EcExpr> }`.

### 3.2 `render.rs` — the renderer

- `pub fn render_file(f: &EcFile) -> String`, plus `render_expr`, `render_type`, `render_stmt`
  used by tests and by story 08's listing.
- Two-space indent per nesting level. Every top-level item ends with `.`. Statements end with `;`.
- **Parenthesisation from a precedence table**, not blanket parens. Minimum viable table, loosest
  first: `=>` (right assoc) < `\/` < `/\` < `^^` < `=` `<>` `<` `<=` `>` `>=` < `+` `-` <
  `*` `%/` `%%` < unary `!` `-` < application < projection/`.[ ]`. An operand binding looser than
  its context gets parens. Add a unit test per row of that table.
- Operator spellings: `=`, `<>`, `/\`, `\/`, `^^`, `=>`, `!`, `%/`, `%%`. Equality of options is
  plain `=`.
- `EcType` spellings: `int`, `bool`, `unit`, `t option`, `(k, v) fmap`, `t distr`, `a -> b`,
  `(a * b)`. Parenthesise tuple and function types inside compound types.
- A `Some e` argument that is not atomic gets parens: `Some (f x)`.
- Deterministic: rendering the same AST twice is byte-identical, and nothing iterates a `HashMap`.

### 3.3 `names.rs` — identifier mangling

```rust
pub enum NameKind { Module, ModuleType, Type, Op, Proc, Var, Field }
pub struct Names { /* per-namespace maps, for collision detection */ }
impl Names {
    pub fn mangle(&mut self, kind: NameKind, raw: &str) -> Result<String, NameError>;
}
```

Rules, applied in order:

1. Replace `-` with `_` (SMT-derived names such as `keys-computed-correctly`).
2. For `Module` / `ModuleType`: uppercase the first letter; prefix `M_` if it starts with a digit
   or `_`.
3. For every other kind: if the name starts with an uppercase letter, or is an EasyCrypt keyword,
   prefix `d_`. `NewKey` → `d_NewKey`, `LTK` → `d_LTK`, `return` → `d_return`, `res` → `d_res`.
   Leading `_` is legal in EasyCrypt (`var _U` compiles) and is left alone.
4. Reserve the `ec_` prefix for the exporter's own generated names (`ec_result`, `ec_tmp0`, …).
   A Domino identifier that already starts with `ec_` gets a `d_` prefix too.
5. Two different raw names mangling to one EasyCrypt name in the same namespace is a
   `NameError::Collision { kind, a, b, mangled }` — a hard error, never a silent rename.

Embed the keyword list from overview §8.1 as a `const KEYWORDS: &[&str]`, sorted, with a comment
naming `ecLexer.mll` as its source.

## 4. Acceptance criteria

- [ ] `src/writers/easycrypt/{mod,ast,render,names}.rs` exist and `cargo build --workspace`,
      `cargo test --workspace`, `cargo clippy --workspace` are clean.
- [ ] A hand-built `EcFile` exercising **every** `EcItem`, `EcStmt`, `EcExpr` and `EcType` variant
      renders to `testdata/easycrypt/story01/kitchen-sink.ec`, checked as a golden file.
- [ ] That golden file **compiles**: `easycrypt compile -I testdata/easycrypt/story01
      kitchen-sink.ec` exits 0. The test skips (not fails) when `easycrypt` is not on `PATH`.
- [ ] Precedence tests: `a /\ b \/ c`, `(a \/ b) /\ c`, `!(a /\ b)`, `a = b /\ c = d`,
      `(a + b) * c`, `a => b => c` each render with the minimal correct parens.
- [ ] Mangling tests: `NewKey`→`d_NewKey`, `LTK`→`d_LTK`, `return`→`d_return`, `res`→`d_res`,
      `_U`→`_U`, `state`→`state`, `keys-computed-correctly`→`keys_computed_correctly`,
      `ec_foo`→`d_ec_foo`; and a collision (`H` vs `d_H`) returns `NameError::Collision`.
- [ ] Rendering is deterministic: two renders of one AST are byte-identical.
- [ ] Nothing outside `src/writers/easycrypt/` changed except the `pub mod` line in
      `src/writers/mod.rs`.

## 6. Notes / risks

- **Do not model tactics.** Proof scripts stay strings; every attempt to type them balloons.
- **`None` needs its type nearly everywhere.** Always render `None<:t>`; a bare `None` is only
  unambiguous when EasyCrypt can infer from context, and guessing when is a bug farm.
- **Don't add a Domino dependency here.** If a variant only makes sense given a Domino concept,
  it belongs in story 02+, not in `ast.rs`.
- **Keep `render.rs` total.** No `panic!`/`todo!` in rendering — an AST that exists must render.
