# Story 45 — Implementation report

## What changed

- `crates/domino/src/cli.rs`: new `EcExport` (`--theorem`, `--force`, `--progress`, help text moved
  unchanged) and `EasycryptCommand::Export`. `Easycrypt` keeps only the global `--project` / `--out`
  and a required subcommand (`subcommand_required = true`, `arg_required_else_help = true`); its
  `command` field is no longer an `Option`. Subcommand order is `export`, `prove`, `debug`,
  `check-alignment` (the enum order; `check-alignment` and `debug` swapped). `EcProve --force`'s help now
  points to `domino easycrypt export --force`. No alias for the bare form.
- `crates/domino/src/main.rs`: `easycrypt()` dispatches `Export(x)` to `easycrypt_translate(&EcExport, …)`
  (the `None` arm is gone); doc comments updated.
- Other pointers to the old spelling: doc comments in `src/debug/render.rs`, `src/debug/lockstep_run.rs`,
  `src/transforms/theorem_transforms.rs`, and `CONTEXT.md` (*Listing*). The `domino` skill, `scripts/`
  and `Readme.md` never named the bare form (grepped).
- Tests that called the bare form now call `easycrypt export`: `easycrypt_progress`,
  `easycrypt_overwrite`, `easycrypt_tactics_writes`, `easycrypt_ctrl_c` (3 sites), `easycrypt_prove`
  (its `domino(…)` helper gets `["export"]` and still appends `--progress none` for it),
  `easycrypt_lockstep_progress`. `easycrypt_stage_messages` already used explicit subcommands.
- New tests in `easycrypt_overwrite.rs`:
  `bare_easycrypt_prints_the_help_and_fails_and_lists_the_subcommands_in_order`,
  `translation_flags_belong_to_export_not_to_the_parent` (the three parse errors of the acceptance
  criteria, and `--project` before / `--out` after the subcommand).

## Verification

- `cargo test --workspace --no-fail-fast --features cvc5-lib` with `DOMINO_EASYCRYPT` set: 728 passed,
  0 failed, 6 ignored.
- `cargo test --workspace --no-fail-fast` (no cvc5-lib): 613 passed, 0 failed, 5 ignored.
- A first `--features cvc5-lib` run, which stops at the first failing binary, failed
  `easycrypt_ctrl_c::ctrl_c_interrupts_the_running_sentence_seals_the_oracle_and_exits_130` (timing
  under load); it passes alone and in both full reruns above.
- `cargo clippy --workspace --all-targets`, with and without `--features cvc5-lib`: only the known
  pre-existing warnings (collapsible `if`, `TempDir::into_path`).
- By hand on hello-world: bare `domino easycrypt` prints the help; `easycrypt --force export` is
  "unexpected argument" (clap's tip even suggests `export --force`).

## Deviations and notes

- `cargo fmt --check` reports many diffs repo-wide, before this story too; not touched.
- `Easycrypt.command` is non-optional now, so a missing subcommand is clap's job, not `main.rs`'s.

## State handed to the next story

- Translation is `domino easycrypt export [--theorem T] [--force] [--progress M]`; no flag other than
  `--project` / `--out` lives on the parent. Tests that need translation call `["easycrypt", "export", …]`.

## Notes for follow-up

- ADRs and earlier stories still say `domino easycrypt` for translation, by design.
