# The export tree is never overwritten without `--force`

**Status:** accepted.

`domino easycrypt` writes its output tree with a bare `std::fs::write` per file and no existence
check, so it silently overwrites whatever is at the destination. Two things in that tree are worth
more than the run producing them: a `Eq_*.ec` whose bullets a **tactics run** proved, possibly over
many minutes, and hand-written EasyCrypt someone put there — `example-projects/4WHS/ec4whs/` is
exactly that, a hand-written development sitting beside a Domino project. Both are destroyed by a
re-run, with no warning and nothing to recover from.

We therefore made the export **refuse to write into a directory that already holds files**. Any
pre-existing file under `<out>/<theorem>/` that is not a **run artifact** stops the whole
invocation, before any translation work and before EasyCrypt is probed, listing every offending
file across every theorem. `--force` overwrites. This holds for every mode, not just `--tactics`:
the hazard belongs to writing, not to tactic generation.

## Considered options

- **Overwrite only files carrying the `(* generated by domino … *)` banner.** Rejected: a tactics
  run's output carries that banner too, so this silently eats the one thing most worth protecting.
- **Overwrite only when the bytes on disk differ from what would be written.** Rejected: it needs
  the export to have run to know what it would write, which contradicts warning as early as
  possible — and the export is the expensive part.
- **Protect `.ec` files only.** Rejected: a hand-written `.smt2` or a note in the output tree is
  just as much someone's work.
- **Stop only the offending theorem and export the rest.** Rejected for consistency with the
  existing all-or-nothing rule (`crates/domino/src/main.rs`): a failed export must not leave a
  half-written tree.

## Consequences

- The exemption is stated as **directories and patterns**, not a fixed file list: the `progress/`
  and `!debug!/` subtrees, `*.report.txt` and `alignment.txt`. A fixed list would be complete today
  and wrong as soon as `docs/stories/symbolic-execution/19-…` moves lockstep output inside the
  export tree, at which point every second run would start demanding `--force`.
- `_build/easycrypt` is a build directory that refuses to be rebuilt in place. That is deliberate
  and it is the surprising part of this decision.
- **Resuming is not addressed.** *(Superseded by ADR 0006 and story 37: a proof job resumes from
  the equivalence's session record, and `--tactics` no longer exists.)* After a stopped tactics run the natural next command is blocked,
  and `--force` discards the **partial proof** it would otherwise pick up. The warning says so
  ("N of M oracles already proved; --force discards them"), and `--oracle` is the manual
  workaround. A real `--resume` means parsing tactic scripts back out of a `.ec` and trusting
  them, which is deferred as its own piece of work.
